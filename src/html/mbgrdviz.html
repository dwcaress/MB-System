NAME


MBgrdviz - Simple interactive 2D/3D visualization of GMT grids.


 

VERSION


Version 5.0


 

SYNOPSIS


MBgrdviz



[--grid-file=grdfile {-Igrdfile}



--help {-H}



--overlay-file=grdfile {-Jgrdfile}



--test {-T}



--verbose {-V}]


 

DESCRIPTION




Overview


MBgrdviz is an interactive 2D/3D visualization tool for GMT topography
grid files. MBgrdviz can be used for general data visualization and also has features
integrating it with swath mapping data processing and swath survey planning.


Once a topographic grid has been read, it may be displayed either as a 2D map or as
a 3D model. The 2D view can be panned and zoomed; the 3D view also allows arbitrary
rotations of both the topography model and the viewpoint.


In addition to the primary topography, other data sets (e.g. sidescan sonar
mosaics) can be read and displayed as overlays on the topography. Navigation
of ships or underwater vehicles can be read and displayed; if associated with
swath data the extent of mapping coverage can be displayed. Site data (individual
point locations) can be read, displayed, interactively created and modified, and
saved. Route data (collections of waypoints) can also be read, displayed,
interactively created and modified, and saved. GIS polylines, polygons, and
points can be read from MB-System files or imported from ESRI shapefiles,
displayed, and saved or exported, but not edited.


The topography data can be shown using a number of colortables. The colortables can
be linearly stretched between minimum and maximum values, or applied using
a histogram equalization. The display may also be shaded using an
illumination model, slope magnitude, or overlay grid data. Overlay data
can be displayed draped on the topography. Topographic
contours can be displayed using a user defined contour interval.


In addition to modifying the view, users can interact with the display in
several ways. Users can pick single points on the surface to determine position
and topography values, or pick and drag to determine range and bearing between
two locations. Arbitrary rectangular regions with north-south and east-west boundaries or
arbitrarily oriented rectangular areas can be defined by picking and dragging.
The data within a region can be opened as a new display; areas can be used
for survey planning.


Topographic profiles associated with two-point picks, selected navigation, or
selected routes can be displayed in a separate window and saved.


MBgrdviz can be used to select swath data files for editing or analysis
using other MB-System tools. If survey navigation has been read and
displayed, a user may interactively select files of interest, and then start up
the interactive waterfall bathymetry editor MBedit to work on those files.
Also available are the interactive, visualization based bathymetry editor
MBeditviz, the navigation editor MBnavedit, and the water sound
speed modeling tool MBvelocitytool.


MBgrdviz supports as many as ten displays deriving either from reading
topography grids or extracting user defined regions from existing displays.


Starting Up


When MBgrdviz is invoked on the command line, a single window comes up with
the title MBgrdviz and two menus: File and Help. The Help
menu contains a single item named About, which brings up a simple
information window including the MB-System release version identifier.
The File menu contains several items, but initially only the Open Primary
Grid and Quit items are enabled. Selecting Open Primary Grid brings
up a filesystem browser window that allows users to find and select the desired
GMT topography grid. By default, the browser filter is set to display only
files ending with a ".grd" suffix. Users can change this filter (e.g. setting it
to "*" will display all files) and then hit the Filter button to relist the
files as desired. Once the desired topography grid file has been located and
selected so that its full path appears in the Selection text item, clicking
the OK button will cause MBgrdviz to read the grid and open an MBview
display window. Initially, the topography will be displayed in 2D, or map view mode.
The default color table will be "Haxby", and the topography will be shaded using slope magnitude.


Picking, Zooming, Panning in 2D View


MBgrdviz will initially be in the "pan and zoom" mouse mode.


In this mode, if the cursor is over
topography when the left button is clicked, a red X will appear at the
pick point and an info window on the left side of the MBview display window
will show the longitude, latitude, and topography value of the pick point.
If the left button is used to drag the cursor from one location to another, both
the pick and release points will be shown as red Xs and a red line will be displayed
in between. The info window will show both the start and end positions and also the
range and bearing between the two locations.


The middle button can be used to pan by clicking, holding down, and moving the cursor.


The right button can be used to zoom the display by clicking, holding down,
and moving the cursor up to zoom in or down to zoom out.


Manipulating a 3D View


The user can switch from 2D map view to 3D view mode using the <View->3D Display> menu item
(and can switch back using the<View->Map Display> menu item). In the 3D view mode, picking,
panning, and zooming are done in the same fashion as in the map view. However, the
display is a perspective view that includes both rotation of the topographic model and
of the viewpoint. To rotate the model, select the "Rotate Model" button (or the <Mouse->Rotate Model>
menu item). The left button can be used to pick topography, the middle button will rotate the model
when clicked and dragged, and the right button will change the vertical exaggeration when
clicked and moved up (more exaggeration) or down (less exaggeration). To rotate the viewpoint,
select the "Rotate View" button (or the <Mouse->Rotate View>
menu item). The left button can be used to pick topography, the middle button will rotate the model
when clicked and dragged, and the right button will change the vertical exaggeration when
clicked and moved up (more exaggeration) or down (less exaggeration).


Sites and Routes


Sites are individual named locations; routes are named sequences of waypoints,
such as survey lines or vehicle missions. Both can be read from files,
created and edited interactively, and saved (see the site and route file
formats below). To edit sites, select the <Mouse->Edit Sites> mouse mode;
the middle button adds a site, the left button selects and drags a site, and
the right button deletes the selected site. To edit routes, select the
<Mouse->Edit Routes> mouse mode; with no route selected the middle button
starts a new route, with a waypoint selected the middle button adds a new
waypoint after it, the left button selects and drags waypoints, and the right
button deletes the selected waypoint. Route segments are draped on the
topography, and the route lengths both in plan view and along the
topography are shown in the Route List. Routes can be saved in the
MB-System route format or exported in several formats used by survey and
vehicle control software.


Navigation and Swath Data


The navigation of swath (or other) data files can be displayed by opening an
MB-System datalist with <Action->Open Navigation> or
<Action->Open Swath Data>. The navigation is plotted for the parts of the
files lying within the grid; <Action->Open Swath Data> also gives the
outline of the swath coverage. Where the ancillary navigation (".fnv") or
bathymetry (".fbt") files made by mbdatalist or mbprocess exist,
they are read
instead of the full data files. Using the <Mouse->Select Nav> or
<Mouse->Select Nav File> mouse modes, sections of navigation or whole files
can be selected and then opened in the editing and analysis programs
listed in the <Action> menu.


Profiles


The <View->Profile> item opens a window showing the topographic profile
along the current two point pick, the selected route, or the selected
navigation, whichever was picked most recently. The profile can be saved
with <Action->Save Profile File>.


Regions and Survey Planning


Using the <Mouse->Pick Area> mouse mode, the left button drags out a
rectangular region with north-south and east-west boundaries, and the middle
button drags out the centerline of an arbitrarily oriented rectangular area
whose width is changed with the right button. A region can be opened as a new
display with <Action->Open Region as New View>. An area can be used to
generate a survey route with <Action->Generate Survey Route from Area>.


GIS Polylines, Polygons, and Points


MBgrdviz can display GIS polylines (lines with one or more parts),
polygons (one or more closed rings, each an outer boundary or a hole), and
points, such as survey areas, cable routes, or mooring locations. These are
read from MB-System polyline, polygon, and point files (see below) using
the <Action->Open Polyline File>, <Action->Open Polygon File>, and
<Action->Open Point File> menu items, or imported from ESRI shapefiles using
<Action->Import Shapefile>. A shapefile import reads polylines, polygons, or
points according to the geometry of the shapefile, transforms coordinates in
any projection given by the shapefile's ".prj" file to longitude and
latitude, and keeps only the features that overlap the grid displayed in the
window from which the import was started; features crossing the edge of the
grid are kept whole. Feature names are taken from a NAME, LABEL, or TITLE
attribute, else from an ID attribute (as "layer id"), else from the first
text attribute. Features without COLOR and SIZE attributes are displayed
blue-green (polylines), yellow (polygons), or green (points).


Each file read or imported becomes a layer. The polylines and the polygon
outlines are draped on the topography; parts lying off the grid are drawn
at the top of the grid's depth range. Points are drawn as triangles. The
GIS data are shared by all MBview windows like sites and routes, and
are displayed or hidden in each window with the <View->Polylines>,
<View->Polygons>, and <View->Points> toggles. The <Controls->Polyline
List>, <Controls->Polygon List>, and <Controls->Point List> windows list
the layers and features; there features and whole layers can be recolored,
shown or hidden, and deleted. Polylines can be converted to routes (which
can then be edited and saved as route files), and routes can be converted
to polylines. The GIS data are not otherwise edited. All features of each
type can be saved to MB-System files or exported as shapefiles.

OPTIONS





--help -H



This "help" flag cause the program to print out a description
of its operation and then exit immediately.

--grid-file=grdfile -Igrdfile



Sets a GMT grid file to be read and displayed at startup.
This option is usually used only when MBgrdviz is started
automatically from some other process.

--overlay-file=grdfile -Jgrdfile



Sets a GMT grid file to be read and displayed as an overlay at startup.
This option has no effect unless the -I option is also used to
specify a primary grid file.

--test -T



Sets a test grid to be calculated and displayed at startup.This
allows the program to be tested even when a grid file is
unavailable.

--verbose -V



Normally, MBgrdviz outputs limited information to the stderr stream.
If the -V flag is given, then MBgrdviz works in a "verbose" mode and
outputs the program version being used, all error status messages,
and a large amount of other information including all of the
beams flagged or zeroed.




 

INTERACTIVE CONTROLS: MBgrdviz Startup Window





[MBgrdviz]:<File->Open Primary Grid>



This menu button pops up a file browser that allows the user to
select an input GMT grid file. If the OK button is clicked, MBgrdviz will
attempt to read a topography grid from the specified file. If successful,
a new MBview window will appear displaying the topography. This item
is active until all ten MBview windows are in use.

[MBgrdviz]:<File->Open Site>



This menu button pops up a file browser that allows the user to
select an input site file (see the site file format below). A site file
specifies one or more individual locations that can be displayed and
interactively moved. Sites are shared by all MBview windows. This
item, like the other file items below, is active once an MBview window
is open, and acts on the first MBview window; the <Action> menu of each
MBview window has the same items acting on that window.

[MBgrdviz]:<File->Open Route>



This menu button pops up a file browser that allows the user to
select an input route file (see the route file format below).

[MBgrdviz]:<File->Open Navigation>



This menu button pops up a file browser that allows the user to select an
MB-System datalist of data files whose navigation is to be displayed
(see <Action->Open Navigation>).

[MBgrdviz]:<File->Open Swath>



This menu button pops up a file browser that allows the user to select an
MB-System datalist of swath data files whose navigation and swath
coverage are to be displayed (see <Action->Open Swath Data>).

[MBgrdviz]:<File->Open Vector>



This menu button pops up a file browser that allows the user to select a
vector file (see the vector file format below).

[MBgrdviz]:<File->Open Polyline>




[MBgrdviz]:<File->Open Polygon>




[MBgrdviz]:<File->Open Point>



These menu buttons pop up a file browser that allows the user to select an
MB-System polyline (".pln"), polygon (".plg"), or point (".pts") file to be
read and displayed in the first MBview window, as with the
corresponding items of the MBview <Action> menu.

[MBgrdviz]:<File->Save Site>



This menu button pops up a file browser that allows the user to specify an
output site file to which all sites are written. It is active when sites exist.

[MBgrdviz]:<File->Save Route>



This menu button pops up a file browser that allows the user to specify an
output route file to which the selected routes, or all routes if none are
selected, are written. It is active when routes exist.

[MBgrdviz]:<File->Quit>



This button causes the program to exit (mostly) gracefully.

[MBgrdviz]:<Realtime->Setup>




[MBgrdviz]:<Realtime->Start>




[MBgrdviz]:<Realtime->Stop>




[MBgrdviz]:<Realtime->Pause>




[MBgrdviz]:<Realtime->Resume>



The Realtime menu and its setup dialog are intended for the display of
realtime navigation, which is not yet implemented; the menu is inactive.

[MBgrdviz]:<Help->About>



This button causes the program to bring up a dialog showing the
program's name, version, and authors.

[MBview]:<Action->Open Site File>

These items pop up a file browser that allows the user to select a site file

[MBview]:<Action->Open Navigation>




[MBview]:<Action->Open Swath Data>



These items pop up a file browser that allows the user to select an
MB-System datalist (".mb-1"). The navigation of each data file in the
datalist, within the bounds of the grid, is read and displayed as a track
named for the file; processed files are used where the datalist calls for
them, and ASCII xyz files are skipped. <Action->Open Navigation> reads the
".fnv" navigation files where they exist; <Action->Open Swath Data> reads
the ".fbt" bathymetry files where they exist and also gives the outline of
the swath coverage. The navigation is decimated according to the grid
spacing.

[MBview]:<Action->Open Vector File>



This item pops up a file browser that allows the user to select a vector file

along its tracks.

[MBview]:<Action->Open Polyline File>




[MBview]:<Action->Open Polygon File>

These menu buttons pop up a file browser that allows the user to select an
MB-System polyline (".pln"), polygon (".plg"), or point (".pts") file. All of
the features in the file are read and displayed, whether or not they overlap
the grid, with each layer of the file becoming a layer in MBgrdviz.

[MBview]:<Action->Import Shapefile>



This menu button pops up a file browser that allows the user to select an ESRI

[MBview]:<Action->Save Route File Reversed>



This item writes the selected routes, or all routes, as a route file with the

[MBview]:<Action->Save Risi Script File (variable heading)>




[MBview]:<Action->Save Risi Script File (static heading)>




[MBview]:<Action->Save Risi 2 Script File (variable heading)>




[MBview]:<Action->Save Risi 2 Script File (static heading)>



These items write the selected routes, or all routes, as mission scripts for
the Risi vehicle controller, with the waypoints given in meters relative to the
first waypoint. The Risi 2 scripts give each leg as a relative turn
("heading rel") and a move ("move bearing range, bearing", with the bearing
relative to the vehicle heading), assuming that the vehicle starts at the first
waypoint with heading 0. With variable heading the vehicle turns to face along
each leg; with static heading it turns once to the bearing of the first leg,
keeps that heading on all legs, and turns back to heading 0 at the end.

[MBview]:<Action->Save Route as Greensea YML File>

[MBview]:<Action->Save Route as TECDIS LST File>

[MBview]:<Action->Save Route as Kongsberg DP waypoint File>

[MBview]:<Action->Save Route as SIS ASCIIPlan line File>




[MBview]:<Action->Save Route as SIS ASCIIPlan route File>



These items write all routes as Kongsberg SIS ASCII survey plan files, either

[MBview]:<Action->Save Profile File>



This item writes the current profile (see the profile file format below). It

[MBview]:<Action->Open Selected Nav in MBedit>




[MBview]:<Action->Open Selected Nav in MBnavedit>

These items start MBedit, MBnavedit, or MBvelocitytool on the

[MBview]:<Action->Open Selected Nav in MBeditviz>



This item writes a temporary datalist of the data files containing the

This item opens the survey route dialog (see below), which generates a

MOUSE ACTIONS


The actions of the mouse buttons in the display depend on the mouse mode, set
with the <Mouse> menu; the current actions are listed in the "Mouse Mode" box
on the left side of the window. On release of a button the display is redrawn
at medium resolution.



Left Mouse Button



In the Pan & Zoom, Rotate Model, Rotate View, Shading, Select Nav, and Select
Nav File modes, clicking picks a point on the topography, marked with a red X
and described in the "Pick Info" box; dragging picks two points and reports
the range and bearing between them, and gives the profile between them. In
the Pick Area mode, dragging defines a region with north-south and east-west
boundaries; dragging from near a corner of an existing region moves that
corner. In the Edit Sites mode, clicking selects the nearest site and
dragging moves it. In the Edit Routes mode, clicking selects the nearest
waypoint (and its route) and dragging moves it; clicking off the grid clears
the selection.

Middle Mouse Button



In the Pan & Zoom mode, dragging pans the view. In the Rotate Model and
Rotate View modes, dragging rotates the model or the viewpoint in azimuth
(left and right) and elevation (up and down). In the Shading mode with
shading by illumination, dragging moves the light source. In the Pick Area
mode, dragging defines the centerline of an area; dragging from near an end
of an existing area moves that end. In the Edit Sites mode, clicking adds a
new site after the selected site and dragging moves it. In the Edit Routes
mode, clicking with no route selected starts a new route; with a waypoint
selected, clicking adds a new waypoint after it (after the last waypoint to
extend a route, or between waypoints to insert one), and dragging moves the
new waypoint. In the Select Nav mode, dragging selects the navigation between
the two picked points; in the Select Nav File mode, it selects all of the
navigation files from the first to the second picked file.

Right Mouse Button



In the Pan & Zoom and Rotate View modes, dragging up zooms in and dragging
down zooms out. In the Rotate Model mode, dragging up or down increases or
decreases the vertical exaggeration. In the Shading mode, dragging up or down
increases or decreases the shading magnitude. In the Pick Area mode, dragging
up or down widens or narrows the area. In the Edit Sites and Edit Routes
modes, clicking on the selected site or waypoint deletes it; deleting the
last waypoint of a route deletes the route. In the Select Nav and Select Nav
File modes, the right button deselects navigation as the middle button
selects it.

MBGRDVIZ ROUTE FILES


MB-System route files (suffix ".rte") are text files beginning with a header
line "## Route File Version 2.00" and further comment lines beginning with
"##" that describe the format. Each route begins with a line
"> ## STARTROUTE np,color,size,editmode,name", where np is the number of
points, color is a color number as for the GIS files (0 = black to
7 = purple), size is the line width, editmode is 1 if the route can be
edited, and the name is the rest of the line, and ends with a line
"> ## ENDROUTE".
Between these lines are the points of the route, one per line, with the comma
separated values:




longitude (deg), latitude (deg), topography (m), waypoint type,
bearing (deg), lateral distance (m), distance along topography (m),
slope (m/m)



The waypoint type is 0 for points that only give the topography between
waypoints, 1 for a simple waypoint, 2 for a transit waypoint, and 3 to 12 for
the start and end of survey lines of types 1 to 5 (3 = start line, 4 = end
line, 5 = start line 2, and so on); waypoints are followed by a comment such
as "## WAYPOINT STARTLINE". When a route file is read, only the longitude,
latitude, and waypoint type of the waypoints (type 1 or greater) are used; the
topography points are recalculated from the grid. Lines beginning with ">"
end the current route.


Files without the version header are also read: each line gives at least the
longitude and latitude of a waypoint, separated by commas or white space,
optionally followed by the topography and the waypoint type, and routes are
separated by lines beginning with ">". In such files the comment lines
"## ROUTENAME name", "## ROUTECOLOR color", "## ROUTESIZE size", and
"## ROUTEEDITMODE mode" set the route properties. For example, a file
giving a route of two survey lines and a route of one survey line:




## ROUTENAME Lines A
## ROUTECOLOR 1
-121.12 34.00 0 3
-121.02 34.06 0 4
-121.02 34.07 0 3
-121.12 34.01 0 4
>
## ROUTENAME Lines B
-121.12 33.98 0 3
-121.02 34.04 0 4





The route export formats of the <Action> menu are written for particular
survey and vehicle control systems and are not read by MBgrdviz.


 

MBGRDVIZ SITE FILES


MB-System site files (suffix ".ste") are text files beginning with a header
line "## Site File Version 2.00" and further comment lines beginning with
"#". Each other line gives one site, with the comma separated values:




longitude (deg), latitude (deg), topography (m), color, size, name



where the color is a color number as for the GIS files (0 = black to
7 = purple), and the name is the rest of the line. Only the longitude and
latitude are required. Longitudes and latitudes may also be given as degrees
and decimal minutes separated by a colon (e.g. -121:04.2). Files with version
1 headers, or without a header and without commas, are read with white space
separated values. For example:




## Site File Version 2.00
-121.0800000,  34.0200000, -1650.000, 4, 1,M1
-121.0500000,  34.0500000, -2010.000, 7, 1,M2 deep mooring





 

MBGRDVIZ VECTOR FILES


Vector files are text files giving tracks of points with data values to be
displayed as colored balls. Each line gives the white space separated
longitude (deg), latitude (deg), z (m), and data value of one point; lines
beginning with ">" separate tracks, and lines beginning with "#" are
comments, except that "## VECTORNAME name" sets the name (a single word)
of the track and "## MIN value" and "## MAX value" set the range of data values
spanned by the colors (by default the range of the data).


 

MBGRDVIZ PROFILE FILES


Profile files written with <Action->Save Profile File> are text files with a
header of comment lines beginning with "##", including the profile source,
length, and depth range, followed by one line per profile point with the
white space separated values: distance along the profile (m), topography (m),
segment boundary flag, longitude (deg), latitude (deg), distance along the
topography (m), bearing (deg), and slope (m/m).


 

MBGRDVIZ POLYLINE FILES


MB-System polyline files (suffix ".pln") are text files. The file begins with
a header line identifying the file type and version,
followed by comment lines beginning with "##". A "## Z values: present" or
"## Z values: absent" line records whether the z values are meaningful, and
lines of the form

## LAYER l,layer name



give the names of the layers. Colors are given as integers:
0 = black, 1 = white, 2 = red, 3 = yellow, 4 = green, 5 = blue-green, 6 = blue,
and 7 = purple (red is used to highlight selected features). Sizes are line
widths in pixels for polylines and polygons, and larger symbols for points with
sizes above 1. Positions are longitude and latitude in decimal degrees (WGS84)
and z values are in meters, positive up.
Each polyline begins with a
line "> ## STARTPOLYLINE npart,npoint,color,size,layer,name", each of its parts
begins with a line "> ## PART ipart,npoint" followed by the comma separated
longitude, latitude, and z values of its points, and the polyline ends with a
line "> ## ENDPOLYLINE". The name is the rest of the line and may contain spaces
and commas. Because the "##" lines are comments and the ">" lines are segment
headers for GMT, the files can also be plotted directly with GMT.
For example:




## Polyline File Version 1.00
## Z values: absent
## LAYER 0,survey lines
> ## STARTPOLYLINE 2,5,1,3,0,Line A
> ## PART 0,3
-121.120000000,34.000000000,0.000
-121.070000000,34.030000000,0.000
-121.020000000,34.060000000,0.000
> ## PART 1,2
-121.120000000,34.060000000,0.000
-121.020000000,34.000000000,0.000
> ## ENDPOLYLINE





 

MBGRDVIZ POLYGON FILES


MB-System polygon files (suffix ".plg") have the same form as polyline files,
with polygons beginning with a line
"> ## STARTPOLYGON nring,npoint,color,size,fillcolor,layer,name"
(the fill color is -1 for no fill; filled display is not yet supported), rings
beginning with a line "> ## RING iring,npoint,OUTER" for outer boundaries or
"> -Ph ## RING iring,npoint,HOLE" for holes (the -Ph marks a hole for
GMT), and polygons ending with a line "> ## ENDPOLYGON". Each ring is
closed, its last point repeating its first point. For example:




## Polygon File Version 1.00
## Z values: absent
## LAYER 0,study areas
> ## STARTPOLYGON 2,10,3,2,-1,0,Closure with hole
> ## RING 0,5,OUTER
-122.000000000,36.000000000,0.000
-121.000000000,36.000000000,0.000
-121.000000000,37.000000000,0.000
-122.000000000,37.000000000,0.000
-122.000000000,36.000000000,0.000
> -Ph ## RING 1,5,HOLE
-121.800000000,36.200000000,0.000
-121.800000000,36.800000000,0.000
-121.200000000,36.800000000,0.000
-121.200000000,36.200000000,0.000
-121.800000000,36.200000000,0.000
> ## ENDPOLYGON





 

MBGRDVIZ POINT FILES


MB-System point files (suffix ".pts") have the same header and layer lines as
polyline files, followed by one line per point giving the comma separated
longitude, latitude, z, color, size, layer, and name. For example:




## Point File Version 1.00
## Z values: absent
## LAYER 0,moorings
-121.080000000,34.020000000,0.000,4,2,0,M1
-121.050000000,34.050000000,0.000,7,1,0,M2





 

SHAPEFILES


MBgrdviz imports and exports ESRI shapefiles using the GDAL library.
Imported shapefiles may contain points, multipoints (each point becomes a
separate feature), lines, multilines, polygons, or multipolygons, with or
without z values,
in any coordinate system given by a ".prj" file (without a ".prj" file the
coordinates are taken to be longitude and latitude). Exported shapefiles use
WGS84 longitude and latitude, are encoded in UTF-8, and have NAME, COLOR, and
SIZE attributes (and FILLCOLOR for polygons), so that they can be imported again
with the same names, colors, and sizes. Shapefile attribute text is limited to
254 bytes, so longer names are shortened on export.

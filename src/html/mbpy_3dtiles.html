NAME

mbpy_3dtiles - Create an executable shellscript which will make the standard 3D products of a survey (GLBs, OGC 3D Tiles tilesets and X3DOM and CesiumJS pages) with mbgrd2gltf, mbmesh and mbglb2tiles.

VERSION

Version 5.0

SYNOPSIS

mbpy_3dtiles [-Isurveydir] [-Oroot] [--subdirname] [--gridname] [--datalistname]
[--geoorigin=lon,lat,elev] [--liftmeters] [--reference-subdirname] [-Lmeters] [--threadsn] [--no-label-chunks]
[--x3dom-urlurl] [--no-cesium-html] [--cesium-urlurl] [--no-survey-page] [--mbgrd2gltf-args=args] [--mbmesh-args=args] [--mbglb2tiles-args=args]
[--force] [-X] [-V]

DESCRIPTION

mbpy_3dtiles is a macro that writes a shellscript, root.sh (default 3dtiles.sh, in the survey directory), and with -X runs it. It is meant to be run in a survey directory that has a subdirectory for each kind of data, by default multibeam and lidar, each with a grid, ZTopo.grd, and a datalist of processed swath data, datalistp.mb-1. A subdirectory, or a file in it, that is not there is left out. The commands, in the order that they run, with paths relative to the survey directory:
1. mbgrd2gltf --input dir/ZTopo.grd --html --cesium-html --geoorigin --output dir/ZTopo
2. mbmesh --input dir/datalistp.mb-1 --html --cesium-html --threads --geoorigin -L --raw-mesh-glb --pointcloud-glb --track-glb --label-chunks --output dir/mbmesh_output
3. mbglb2tiles of dir/ZTopo.glb (to dir/ZTopo_tileset) and of dir/mbmesh_output/mesh.glb, each with --html --cesium-html --x3dom-url --lift
4. mbmesh --input . --html --cesium-html --geoorigin --x3dom-url, the survey pages, mbmesh_survey.html and mbmesh_survey_cesium.html.

There is one GeoOrigin for a survey, which every program gets so that the models line up, and one lift, which every tileset gets. Without --geoorigin the GeoOrigin is the center of the grid of the reference subdirectory (multibeam) and the mean of its heights, read with gmt grdinfo; without --lift the lift puts the lowest point of that grid 10 m above the ellipsoid, to a meter. The other subdirectories, the lidar for example, get the same ones. ZTopo.grd is a standard product of a survey, which this macro does not make: a subdirectory that has a datalist and no grid, or a grid and no datalist, gets a warning on standard error that says what will not be made, whatever -V says.

A full run takes hours, so the shellscript runs a command only if it has something to do: if one of its outputs (the GLBs, the tilesets and the pages that it writes) is missing or older, by modification time, than one of its inputs. The inputs are the grid, for mbgrd2gltf; the datalist and every swath file that it names, the processed files too, for mbmesh; the GLB, for mbglb2tiles; and the outputs of all the other commands, for the survey pages. The commands run in order, so what an earlier command makes again makes what depends on it stale. The shellscript checks when it runs, not when it is written. A command that is not run is reported as up to date. A change of an option cannot be seen this way: use --force, or FORCE=1 in the environment of a shellscript made without it.

The pages and their logs need a web server: from the survey directory, python3 -m http.server.

OPTIONS

-Isurveydir, --input
The survey directory [the current directory].
-Oroot, --output
The shellscript is root.sh [3dtiles].
--subdir name
A subdirectory to process; can be repeated [multibeam, lidar].
--grid name, --datalist name
The names of the grid and the datalist [ZTopo.grd, datalistp.mb-1].
--geoorigin=lon,lat,elev
The GeoOrigin, with the height above the ellipsoid. A value that begins with a minus has to be attached with an equals sign.
--lift meters
How far the tilesets are lifted above the ellipsoid.
--force
Make every product again, whatever the modification times say.
--reference-subdir name
The subdirectory whose grid sets the GeoOrigin and the lift of the whole survey [multibeam].
-Lmeters, --lod
The smallest feature size of mbmesh [0.1].
--threads n, --no-label-chunks
Chunks that mbmesh reconstructs at once [8]; leave the chunk outlines out of the pages.
--x3dom-url url
The X3DOM script of the pages of mbglb2tiles and the survey page [./x3dom-full.js]; it is relative to each page.
--no-cesium-html
Leave out --cesium-html, the pages for CesiumJS, from every command.
--cesium-url url
The directory of the CesiumJS build that the pages for CesiumJS load, given to each command as --cesium-url [the default of each program, release 1.114 from Cesium's web site].
--no-survey-page
Leave out the survey page.
--mbgrd2gltf-args=args, --mbmesh-args=args, --mbglb2tiles-args=args
More options for the programs, as one quoted string.
-X
Run the shellscript.
-V
Print how the GeoOrigin and the lift were set and the commands, each marked "will run" or "skipped" with the reason, as the modification times are now: an output that is missing, an input that is newer than an output, or an input that an earlier command that will run makes again; with --force every command will run. The shellscript looks at the files again each time it runs, so this is what it would do if it were run now.

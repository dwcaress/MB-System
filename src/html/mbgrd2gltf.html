NAME

mbgrd2gltf - convert bathymetric grid data to GLTF format with optional settings, including Draco compression.

SYNOPSIS

mbgrd2gltf --input FILE [--no-binary] [--output ROOT] [--exaggeration NUM] [--geoorigin[=LON,LAT,ELEV]] [--no-draco] [--draco-precision METERS] [--draco-normal-bits NUM] [--no-colors] [--html] [--cesium-html [--cesium-url URL]] [--geoviewpoint=VALUES] [--verbose] [--help]

Legacy single-dash syntax:
mbgrd2gltf -IFILE [-B] [-OROOT] [-ENUM] [-G[LON,LAT,ELEV]] [-D] [-QpNUM] [-QnNUM] [-QtNUM] [-QcNUM] [-W] [-V] [-H]

DESCRIPTION

mbgrd2gltf is a tool designed to convert grid data files (GRD) to Graphics Library Transmission Format (GLTF) files. It writes binary GLTF (GLB) by default, which is more compact, and can write text-based GLTF with --no-binary; it can exaggerate vertex altitude to enhance topographic features. The grid is written as blocks of 256 by 256 cells, each its own glTF primitive, to handle large datasets efficiently. Draco compression, which is the default, reduces the output GLTF file size by about a factor of ten while keeping the positions to a stated precision (by default a millimeter).

The output mesh vertices are positioned in an Earth-Centered, Earth-Fixed (ECEF) Cartesian coordinate system with units in meters. ECEF is a 3D right-handed coordinate system with its origin at Earth's center of mass, the Z-axis pointing toward the North Pole, the X-axis intersecting the equator at the prime meridian, and the Y-axis completing the right-handed system at 90 degrees east longitude.

Grid node positions follow GMT conventions: for a gridline-registered grid the nodes lie on the edges of the region and are spaced (max - min) / (N - 1) apart, and for a pixel-registered grid (node_offset = 1) the nodes are at the cell centers. Both the old GMT netCDF layout and netCDF CF grids with x and y coordinate variables are read, with rows running either north to south or south to north.

For improved rendering precision in localized areas, the --geoorigin option allows vertices to be expressed as offsets from a local origin point rather than from Earth's center. ECEF coordinates typically have magnitudes on the order of millions of meters, which can cause precision loss when using GPU single-precision floating point arithmetic. By specifying a GeoOrigin near the area of interest, coordinate magnitudes are reduced to thousands of meters, significantly improving rendering quality. The GeoOrigin can be explicitly specified with longitude, latitude, and elevation values, or automatically computed from the grid's geographic center and mean altitude. When no GeoOrigin is specified, vertices use the full ECEF coordinates.

OPTIONS

--input, -I
FILE
Input GMT GRD format bathymetry grid file. This option is required.

--no-binary
Write text-based GLTF (a .gltf file of JSON with the buffers embedded) in place of the binary GLTF (GLB, a .glb file) that is written by default. Binary GLTF is more compact and typically loads faster. --binary, -B are still accepted and do nothing, since binary is the default.

--output, -O
ROOT
Specify the output file root. The appropriate file extension (.gltf or .glb) will be appended automatically. Default: input file basename in the same directory.

--exaggeration, -E
NUM
Specify the vertical exaggeration factor as a decimal number. The relief is scaled about the mean altitude of the grid, so the model stays in place and each altitude's distance from the mean is multiplied by the factor. This can enhance the visibility of topographic features. The result does not depend on the GeoOrigin. Default: 1.0 (no exaggeration).

--geoorigin[=LON,LAT,ELEV], -G[LON,LAT,ELEV]

Specify a GeoOrigin point for high-precision local coordinates. All vertex coordinates will be expressed as offsets from this origin point in the ECEF coordinate system. This improves rendering precision for localized areas by reducing the magnitude of coordinate values, which helps overcome GPU single-precision floating point limitations.
With values (e.g., --geoorigin=-122.0,36.8,-1000): use specified GeoOrigin.
Without values: automatically compute and use grid center and mean altitude.
Not specified: vertices use original ECEF coordinates from Earth's center (default).
The value must be attached to the option. For the long form write an equals sign and no spaces, as in --geoorigin=-122.0,36.8,-1000; for the short form put the value directly after -G, as in -G-122.0,36.8,-1000. A value given as a separate argument, such as --geoorigin -122.0,36.8,-1000, is not accepted, and neither is a value with spaces unless it is quoted so that the shell passes it as one argument.
GLB positions are 32-bit floats, so absolute ECEF (magnitudes of about 6.4 million meters) resolves only about 0.5 m; use a GeoOrigin to preserve sub-meter detail.

--no-draco
Write the mesh as arrays. By default the mesh is compressed with Draco (the glTF extension KHR_draco_mesh_compression), as mbmesh(1) compresses its meshes, with the code that the two programs share (src/mbdraco). --draco, -D are still accepted and do nothing, since compression is the default.

--draco-precision METERS
With Draco, keep the positions to this many meters (default 0.001). Each block of the model gets the number of bits (8 to 30) that makes the step of its quantization no more than this over its extent, so a small block gets few bits and a large one more. This replaces --quantize-position and its fixed 16 bits, which gave a step that depended on the size of the block. The options --quantize-position, --quantize-normal, --quantize-texcoord, --quantize-color and -Q are refused with a message that names the new options.

--draco-normal-bits NUM
With Draco, the bits of each normal, 2 to 30 (default 10). The mesh has no normals today, so this changes nothing; it is the option that mbmesh(1) takes.

--no-colors
Do not color the vertices by height. By default every vertex has a color (COLOR_0) from the Haxby table that mbm_grdplot uses, over the range of the grid (the grid value, not the exaggerated height), written as part of the model (about 15 per cent more bytes), and the pages written by --html and --cesium-html have a "color by height" check box that turns the colors off, which shows the model in one gray, as the pages of mbmesh do. The same table colors the tiles of mbmesh and mbglb2tiles.
--html, -W
Generate an HTML viewer page with inline 3D visualization using X3DOM. The HTML file includes the glTF/GLB model with interactive navigation controls, processing provenance metadata (command line, timestamps, grid parameters, GeoOrigin settings, compression options), and links to MB-System and X3DOM documentation. The viewer requires serving the files via HTTP to avoid browser CORS restrictions when loading local files. The program does not start a web server or a browser; it logs the command to run (python3 -m http.server 8000 --bind 127.0.0.1 --directory <output directory>) and the URL to open. The processing log is written to <output_root>.log, one message a line, and the page loads it when its Processing Log panel is first opened, so the page need not hold it. Output file: <output_root>.html

--cesium-html
Also write a viewer page for CesiumJS, <output_root>_cesium.html beside the model, which has a check box for the model, a link to the log, the Viewpoint menu (overview looking down, 45 and 15 degrees from the south, and the --geoviewpoint viewpoints), a Copy viewpoint button and the scale axes. The globe of Cesium would hide data below the ellipsoid, so the page starts with it hidden and has a check box that shows it, translucent. The mesh has no normals, so the page shades it from the relief of what it sees; with --exaggeration the scale axes say what the Up axis stands for. It must be served over HTTP, like the --html page.
--cesium-url URL
The directory of the CesiumJS build that the --cesium-html page loads, with Cesium.js and Widgets/widgets.css in it (default https://cesium.com/downloads/cesiumjs/releases/1.114/Build/Cesium).
--geoviewpoint=VALUES
With --html or --cesium-html, add a GeoViewpoint to the page; the option can be repeated, and each adds a GeoViewpoint, written with its position as latitude, longitude and elevation and the GeoOrigin used again, named USER_GEOVIEW_1, USER_GEOVIEW_2 and so on, to the Viewpoint menu of the page, after the two overview viewpoints, where Page Down also steps through them. The values are geodetic, in the order of --geoorigin, longitude first, so they do not depend on the GeoOrigin or the data and can be used again in another run: lon,lat,elev,clon,clat,celev, the camera position and the point it looks at, or lon,lat,elev,ax,ay,az,angle,clon,clat,celev, with the orientation as an axis and an angle, as a GeoViewpoint takes it. Heights are above the ellipsoid. Without an orientation the top of the view is toward local up. The Copy GeoViewpoint button of the page gives the ten-number form for the view on the screen, on the clipboard and in the X3DOM log. The value must be attached to the option, with an equals sign and no spaces, for example --geoviewpoint=-122.4,36.6,-900,-122.39,36.61,-950.

--verbose, -V
Enable verbose output showing NetCDF reading details and memory allocation information.

--help, -H
Display help message and exit.

GEOREFERENCE AND PROVENANCE METADATA

The glTF file records where the model is on the Earth and how it was made in its asset.extras, in three blocks. georeference gives the coordinate reference system (EPSG:4978), whether the vertices are absolute or relativeToCenter, the center (the GeoOrigin as ECEF meters, with absolute = vertex + center), the same point as geodeticCenter (longitude, latitude, height), the heightReference (the ellipsoid) and the extent of the grid. provenance gives the software and version, the time of execution (UTC), the command line, working directory, user and host, and the input grid file. MB-System gives the grid size, spacing and registration, the vertical exaggeration, the vertical reference, and content.compression (the Draco bits and step) when the mesh is compressed. The page written by --html holds the same in X3D GeoMetadata and WorldInfo nodes. The names are shared with mbmesh(1) and are described in src/mbmesh/GEOREFERENCE.md. The grid value is used as a height above the WGS 84 ellipsoid, with no geoid correction.

EXAMPLES

Convert a GMT GRD file to a GLTF file with default settings:

mbgrd2gltf --input input.grd

Convert a GRD file to GLB (Binary GLTF) with specified output folder, keeping the positions to a centimeter (Draco compression is the default):

mbgrd2gltf --input input.grd --binary --output /path/to/output/mymodel --draco-precision 0.01

Convert with vertical exaggeration, without compression, and verbose output:

mbgrd2gltf --input input.grd --output /path/to/output/mymodel --binary --no-draco --exaggeration 20 --verbose

Convert bathymetry with 10x vertical exaggeration:

mbgrd2gltf --input bathymetry.grd --exaggeration 10.0 --binary

Convert bathymetry with a GeoOrigin for improved precision:

mbgrd2gltf --input monterey.grd --geoorigin=-122.0,36.8,-1000 --binary

Convert using automatic GeoOrigin (grid center):

mbgrd2gltf --input monterey.grd --geoorigin --binary

Generate HTML viewer with 3D visualization:

mbgrd2gltf --input bathymetry.grd --exaggeration 10 --html --binary

Legacy syntax (still supported):

mbgrd2gltf -I input.grd -B -O /path/to/output/mymodel -D -Qp 20 -E 10 -V
